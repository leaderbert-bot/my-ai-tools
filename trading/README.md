# trading/

| 檔案 | 用途 |
|---|---|
| `加碼SOP.md` | 順勢加碼 SOP 參考手冊（10 種走勢、加碼前 5 問、分批出場、交易紀錄表） |
| `backtest_pyramid.py` | 加碼策略回測：同一套進出場，比較 6 種部位管理方式 |
| `data/GOOG_2004_2013.csv` | 內建示範資料（真實 GOOG 日線，2004-08 ~ 2013-03） |

## 回測怎麼跑

```bash
pip install pandas numpy yfinance

# 內建示範資料
python3 trading/backtest_pyramid.py

# 台股（需要網路，yfinance 代號加 .TW，上櫃加 .TWO）
python3 trading/backtest_pyramid.py --symbols 2330.TW,2317.TW,2454.TW,3231.TW --start 2015-01-01

# 自己的 CSV（欄位 Date,Open,High,Low,Close,Volume）
python3 trading/backtest_pyramid.py --csv my_stock.csv

# 參數網格（突破 20/40/55 天 × 出場 MA10/MA20 × 有無量能），看哪種部位管理最穩
python3 trading/backtest_pyramid.py --symbols 2330.TW --grid

# 列出每一筆交易的試單、加碰、出場
python3 trading/backtest_pyramid.py --trades
```

台股成本建議用 `--fee 0.0029`（手續費 0.1425% + 證交稅 0.3% 攤到單邊）。

## 六種變體

| 代號 | 做法 |
|---|---|
| A | 不加碼，訊號出現就一次進滿倉 |
| B | SOP 金字塔：試單 25%，回檔不破後轉強時加 30/25/20%，加碼後整體停損上移到打平，加碼單有獨立停損 |
| B2 | 同 B 的加碼時機和獨立停損，但整體停損不上移 |
| C | 追高加碼：連續 3 根紅 K 後加碼，停損不動（多數人的習慣） |
| C2 | 同 C，但加碼後停損上移到打平 |
| D | 攤平：價格跌破上一筆進場價 5% 就加 |

所有變體共用同一套進場（突破前 N 日高、站上 20 日線、量能）、同一個初始停損（前 5 日低）、同一個出場（整體停損或收盤跌破出場均線），滿倉金額也一樣。差別只有「怎麼把部位買進去」。

## 怎麼看結果

- **平均R**：每筆交易平均賺幾個「初始風險」。這是比較部位管理好壞最公平的數字，因為它不受交易次數和報酬複利影響。
- **賺變賠%**：曾經浮盈超過 0.5R、最後卻虧損出場的交易佔比。
- **最大單筆虧損R**：不加碼的變體會出現 -1R 以上（跳空），加碼變體因為試單只有 25%，最差約 -0.27R。

## 把自己的策略放進去

進場、停損、出場都集中在 `run()` 裡標了「收盤後決策」和「盤中停損」的區塊，指標在 `add_indicators()`。把進場條件 `sig = ...` 和出場條件 `c[i] < ma10[i]` 換成自己的規則，六種部位管理方式會自動套用同一套規則，直接比較。
